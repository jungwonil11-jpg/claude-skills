# claude-skills

Claude Code 글로벌 skill 모음. 새 컴퓨터에서 셋업하면 모든 프로젝트에서 `/강사싱크`, `/공부시작`, `/노션메모`, `/노션정리`, `/푸쉬`, `/스킬푸쉬`, `/연습`, `/연습100`, `/힌트`, `/채점` 사용 가능.

## 새 컴퓨터 셋업 (한 번만)

> **Windows 전용.** 셋업 스크립트(`setup.bat`)와 statusline·hook(`*.ps1`)이 cmd/PowerShell 기반이라 macOS·Linux에서는 그대로 동작하지 않습니다.

이 레포를 `~/.claude/claude-skills/`에 clone하고, **각 스킬 폴더를 `~/.claude/skills/`로 junction 링크**. 기존 `~/.claude/skills/` 안에 다른 스킬이 있어도 **건드리지 않고 공존**.

```cmd
git clone https://github.com/jungwonil11-jpg/claude-skills %USERPROFILE%\.claude\claude-skills
```

> **본인이 아닌 사용자**라면 위 URL을 그대로 쓰지 말고, 먼저 이 repo를 **fork**한 뒤 본인 fork 주소로 clone하세요. 원본 URL로 clone하면 `/스킬푸쉬`가 push 권한이 없는 원본 repo로 올리려다 실패합니다.

클론된 `claude-skills` 폴더의 **`setup.bat`을 더블클릭**하면 끝. (cmd로 돌리려면: `cd %USERPROFILE%\.claude\claude-skills && setup.bat`)

`setup.bat`이 각 스킬 폴더(`강사싱크/`, `노션메모/` ...)에 대해 `~/.claude/skills/<이름>`을 junction으로 만듭니다.

- **Junction은 관리자/개발자모드 권한 불필요** (심볼릭 링크와 달리)
- 같은 이름 스킬이 이미 있으면 건너뛰고 경고 출력 (덮어쓰기 안 함)

### ⚠️ Claude Code 재시작 필수

셋업 직후엔 슬래시 커맨드가 자동완성에 안 뜸. **Claude Code를 종료했다가 다시 실행**해야 인식됨.
- `/exit` 입력 또는 창 닫기 → 다시 `claude` 실행
- IDE 패널이면 패널 닫고 다시 열기

### 개인 환경 설치 — `/최초셋팅` (Windows)

`setup.bat`은 **스킬 junction만** 만듦. 시니컬 페르소나·statusline·완료/입력대기 토스트 알림 같은 개인 환경은 재시작 후 Claude Code에서 한 번 더:

```
/최초셋팅
```

→ `~/.claude/persona-20대시니컬남성.md` + `statusline.ps1` + `hooks/notify.ps1` 배포 + `settings.json` 머지(기존 키 보존) + BurntToast 설치 + 검증. 끝나면 **Claude Code 한 번 더 재시작**(settings 반영). 머신당 1회.

### 업데이트 / 작업 동기화

별도 복사 단계 없음. 레포에서 직접 작업 → 푸시. Junction이라 `~/.claude/skills/`에서 본 파일은 레포 파일과 같음.

```cmd
cd %USERPROFILE%\.claude\claude-skills
git pull              # 다른 PC에서 push한 변경 받기 (junction이 자동 반영)
git commit -am "..."  # 작업 커밋
git push              # 다른 PC와 공유
```

새 스킬 폴더가 추가됐다면 `setup.bat`을 다시 더블클릭해 누락된 junction 생성.

## Skill 목록

> **이 스킬들은 제 개인 워크플로우에 맞춰져 있습니다.** 국비학원 자바/Spring 수업(`/강사싱크`·`/공부시작` = 강사 upstream + `study` 브랜치), 노션 학습노트(`/노션메모`·`/노션정리`), 코딩 연습 사이클(`/연습`·`/연습100`·`/힌트`·`/채점` = 자바 프리셋 내장, 타 언어는 첫 실행 시 프로젝트 CLAUDE.md에 언어별 룰셋 자동 생성. 단 5-파일 묶음 모드는 자바 Spring/MyBatis 전용), 시니컬 음슴체 페르소나(`/최초셋팅`)가 깔려 있습니다. `/푸쉬`·`/스킬푸쉬`만 워크플로우 독립적입니다.

> 가져다 쓰실 거면 **fork 후 입맛대로 바꾸세요.** 안 쓸 스킬은 fork에서 **폴더째 삭제**하면 됩니다(`setup.bat`은 없는 폴더는 링크하지 않음). 워크플로우가 다르면 각 `SKILL.md`를 직접 고쳐도 됩니다.

## 특정 프로젝트에서 skill 끄기

수업용 skill(`/강사싱크`, `/공부시작`)이 일반 프로젝트 메뉴에 뜨는 게 싫으면, 그 프로젝트에 `.claude/settings.local.json` 추가:

```json
{
  "skillOverrides": {
    "강사싱크": "off",
    "공부시작": "off"
  }
}
```

`.local.json` 은 보통 gitignore 되므로 팀원에게는 안 보이고 본인 PC에만 적용됨.

## /노션정리 사용할 때

## 노션 정리 방식

- 하위 페이지 구성: day별
- 정리 기준: 코드 파일 기준

이후 실행부터는 `CLAUDE.md`를 읽어 그 방식대로 노션 동기화.
수정이 필요하면 `CLAUDE.md`의 해당 섹션을 직접 편집하면 됨.

## /연습 + /힌트 사용법 (원본 구멍 뚫기 방식)

AI 도움 없이 배운 코드를 직접 처음부터 작성해보는 연습 사이클.

### 핵심 워크플로우

1. `/연습` 호출 → 학습 대상 파일을 `.practice-backup/<회차>/`에 백업 + **src/의 실제 파일에 직접 `_____` 빈칸 박음**
2. IntelliJ/VS Code에서 **src/ 실제 위치 파일을 열고 빈칸 채움** — Lombok, JWT, 모든 import 즉시 해결, Ctrl+Space 자동완성, 빨간줄 0개
3. `/채점` → 사용자 답안을 `practice/<회차>/`에 보존 + SCORE.md 작성 + **src/ 원본 자동 복구** (git diff 0)

이전의 격리 폴더 방식(`practice/<회차>/`에 빈칸 파일만 두는 방식)은 5-파일 묶음에서 외부 import 미해결로 빨간줄 폭탄이라 폐기됨. 원본 위치에서 작업하니 IDE 풀 기능 받으면서 실무 환경 그대로.

### 연습 시작

```
/연습
```

1. `src/` 를 탐색해 지금까지 배운 파일을 카테고리별 번호 목록으로 출력
2. 번호 입력으로 파일 선택. 컨트롤러는 자동으로 **5-파일 묶음** 모드 (Controller-Service-ServiceImpl-Mapper-XML 한꺼번에)
3. **퍼센티지 선택** (이전의 0~3 난이도 대신):
   - `33%` — 빈칸 풀의 1/3 (메소드 호출명, getter/setter, 어노테이션 위주)
   - `67%` — 빈칸 풀의 2/3 (+ 변수 타입, 생성자, 문자열)
   - `100%` — 빈칸 풀 전부 (변수명, 메소드명, 접근제어자까지)
4. 5-파일 묶음은 기능 매트릭스가 같이 뜸. **다중 기능 동시 학습**도 지원:
   - 단일: `1 67` (1번 기능을 67%로)
   - 다중: `1,2 67` 또는 `1 2 67` (1번 + 2번을 같이 67%로)
5. src/ 의 실제 학습 대상 파일들이 `_____` 빈칸 박힌 상태로 덮어쓰여짐
6. `practice/<회차>/.state` 파일 생성 (학습 중 마커 — 있는 동안 `/강사싱크`, `/푸쉬` 자동 거절)

### 막혔을 때 — /힌트

빈칸 풀다가 모르겠으면:

```
/힌트              # 진행 중인 회차의 파일 자동 탐지
/힌트 JwtUtil      # 특정 파일 지정 (확장자 생략 OK)
```

- 도메인 개념부터 → 섹션별 빈칸 코드 → 의도 설명 → 정답 코드 순으로 풀어줌
- 사용자가 이미 채운 건 무시하고 원본 기준으로 설명 (평가는 `/채점`의 영역)

### 채점

빈칸 다 채우면:

```
/채점
```

- 진행 중인 회차 자동 탐지 (`.state` 파일 기반)
- 빈칸별 O/X + 점수 매겨서 회차 폴더 안에 **`SCORE_<N>.md`** 작성 (재채점 시 SCORE_2, SCORE_3 누적 — 진척 비교용)
- SCORE는 학습 노트 — 오답마다 **정답 + 왜 틀렸나 + 외우는 법** 박힘
- **src/ 원본 자동 복구** + `.practice-backup/` 삭제 + `.state` 삭제
- 5-파일 묶음이면 PROGRESS.md 진척 매트릭스 갱신 (만점 ✅, 부분 ⌛, 0점 ⬜)

### 학습 산출물

회차 폴더 `practice/<회차>/` 에 영구 보존:
- `README.md` — 회차 정보
- `SCORE_1.md`, `SCORE_2.md`, ... — 채점 결과 누적
- `src/...` 트리 미러 — 사용자 답안 (src/ 트리 구조 그대로)

= git에 commit해서 학습 기록 영구 보관 가능.

### 왜 노션이 아니라 로컬 파일?

이전엔 노션에 빈칸 페이지를 생성했는데, Cloudflare 차단 + 노션 코드 블록 직접 편집 불편 등 비효율적이라 로컬 파일 방식으로 확정. IDE에서 syntax highlighting + Lombok 인식 + 자동완성 다 받으면서 빈칸 채우는 게 학습/채점 모두에 적합.

### 알려진 제한 — VO 단일 파일 33%/67%

VO 단일 파일(`MembersVO`, `GuestBookVO` 등)을 33%/67%로 고르면 룰상 빈칸 풀이 0개라 학습 불가. VO는 100%만 의미 있거나, 룰 완화 합의 후 33%/67% 진행 가능.

이유: 현재 룰은 클래스 레벨 어노테이션(`@Data`, `@AllArgsConstructor` 등)과 필드 선언부를 "빈칸 X" 카테고리로 분류. VO 클래스는 사실상 이 둘로만 구성되어 있어 빈칸 풀이 비게 됨.
